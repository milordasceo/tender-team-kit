# 08. Скрипт tender_finder — установка, запуск, параметры, выходные файлы, ограничения

Подробная справка — `tender_finder/README.md` (в комплекте). Здесь — главное для команды. Главный бот и помощники скрипт **не правят** (см. раздел 9 «Если скрипт сломался»).

## 1. Что делает
Каждый запуск собирает закупки Новосибирской области (регион 54) с небольшой НМЦК из REST-зеркала ЕИС **ГосПлан** (`https://v2test.gosplan.info`), оставляет поставку товаров (режет услуги, работы, лекарства, медизделия стоп-словами и префиксами ОКПД2; **продукты питания и напитки не режет** — префиксы ОКПД2 10 и 11 не исключаются) и по умолчанию (`types: quotes`) оставляет **только запросы котировок**. Отбор по API-запросу: регион, `max_price_ge`/`max_price_le`, этап, срок подачи (`collecting_finished_after` у 44-ФЗ, `submission_close_after` у 223-ФЗ), окно публикации.
Отбор способа (`quotes`, по умолчанию): 44-ФЗ — коды `epNotificationEZK…`; 223-ФЗ — `purchaseNoticeZK`, `purchaseNoticeZKESMBO` (ЗК МСП); общие типы 223-ФЗ (`purchaseNotice`, `purchaseNoticeIS`) — только если способ на карточке «запрос котировок». Аукционы, конкурсы, запросы предложений и закупки у единственного поставщика отсекаются. Другие режимы остаются: `--types без-аукционов` (прежний), `--types все`, `--types аукционы` — только по решению Тэндер Мэна.
Ограничение: префиксы ОКПД2 01–03 (сельхоз-, лесная и рыбная продукция, например свежие овощи, фрукты, рыба) исключены намеренно — такие закупки не берём.

## 2. Установка (на новом компьютере)
```sh
mkdir -p /workspace/tenders
cp -r <распакованный комплект>/tender_finder /workspace/tenders/
cp <распакованный комплект>/api/* /workspace/tenders/      # fz44.yaml, fz223.yaml, fetch.py (справка по API)
cd /workspace/tenders/tender_finder && chmod +x run.sh
python3 --version                                           # нужен Python 3.11+ (только стандартная библиотека)
mkdir -p cache/44 && cp dev_samples/0351300154026000251.json cache/44/   # нужен для offline-test
python3 tender_finder.py --offline-test                     # ожидается: offline-test: OK (5 адресов, 3 карточки, список, CSV)
touch /workspace/tenders/search_sent.txt
```
Живой прогон (только когда работа не на паузе): `./run.sh --price-max 100000 --count-types` — проверка связи без карточек (1–10 запросов), затем обычный прогон.

## 3. Запуск
```sh
cd /workspace/tenders/tender_finder && ./run.sh --price-max 100000
```
Без аргументов читается `config.json`: регион 54, этап «подача заявок», цена 10–80 тыс. ₽ (команда переопределяет до 100 000), законы 44 и 223, только запросы котировок (`types: quotes`), еда не режется, `max_items` 2, публикация со вчерашних 00:00 (Asia/Krasnoyarsk) до сейчас. `run.sh` передаёт все аргументы как есть.

## 4. Параметры (перекрывают config.json)
| Параметр | Смысл |
|---|---|
| `--config PATH` | другой файл настроек |
| `--laws 44` / `223` / `44,223` | законы |
| `--region 54` (можно несколько) | регион |
| `--city-only` / `--no-city-only` | только поставка в г. Новосибирске |
| `--price-min` / `--price-max` | вилка НМЦК, ₽ |
| `--stage 1`/`подача` (2 комиссия, 3 завершена, 4 отменена) | этап |
| `--since` / `--until` | `ГГГГ-ММ-ДД` или ISO |
| `--max-items N` (0 — без ограничения) | максимум позиций |
| `--include` / `--exclude` | подстроки в предмете/позициях |
| `--types` | `quotes`/`котировки` (по умолчанию), `no-auctions`/`без-аукционов`, `all`/`все`, `auctions`/`аукционы` или список кодов (`epNotificationEZK2020,purchaseNoticeZK`) |
| `--count-types` | только распределение типов процедур (карточки и seen.json не трогает) |
| `--ignore-seen` / `--no-save-seen` | не пропускать / не записывать показанные номера |
| `--max-pages N` | страниц списка по 100 |
| `--out-dir DIR` | каталог отчётов |
| `--offline-test` | проверка разбора без сети |
| `-v` | подробный журнал |
Коды котировок: 44-ФЗ `epNotificationEZK2020`, `epNotificationEZK…`; 223-ФЗ `purchaseNoticeZK`, `purchaseNoticeZKESMBO` (ЗК МСП). Общие `purchaseNotice`/`purchaseNoticeIS` решаются по способу на карточке.

## 5. Выходные файлы
- `out/ГГГГ-ММ-ДД.csv` — UTF-8 с BOM, разделитель `;`. Колонки: закон; номер; ссылка; предмет; позиции; кол-во позиций; НМЦК; цена за единицу; заказчик; адрес поставки; окончание подачи; способ; площадка; обеспечение заявки %; обеспечение контракта %; СМП; нацрежим; опубликовано; тип. Повторный запуск в тот же день дописывает только новые строки.
- `out/ГГГГ-ММ-ДД.md` — короткий отчёт (суммы вида `65 794,00 ₽`, время Asia/Krasnoyarsk).
- `out/ГГГГ-ММ-ДД.types.json` — распределение типов процедур.
- `seen.json` — `{"44:НОМЕР": "ГГГГ-ММ-ДД"}`, уже показанные номера (отсеянные фильтром не пишутся).
- `cache/44/`, `cache/223/` — карточки на `cache_ttl_hours` (12 ч).

## 6. config.json (основное)
`laws`, `region`, `city_only`, `city_regex`, `price_min`, `price_max`, `stage`, `since`, `until`, `max_items`, `include_keywords`, `exclude_keywords`, `stop_words`, `exclude_medical_flag`, `okpd2_exclude_prefixes`, `types`, `auction_types`, `base_url`, `min_interval_s` (6.5 с), `max_pages`, `cache_ttl_hours`, `out_dir`, `seen_file`.
Переменные окружения: `GOSPLAN_BASE` (важнее `base_url`), `GOSPLAN_KEY` (заголовок `X-API-Key`, ключ в файлы не класть).
Платный ключ: `GOSPLAN_BASE=https://v2.gosplan.info GOSPLAN_KEY=<ключ> ./run.sh --price-max 100000` — снимает лимит.

## 7. Ограничения
- Лимит ГосПлан v2test — ~10 запросов/мин **общий на IP** (скрипт + ручные запросы помощников). Скрипт держит паузу ≥ 6,5 с, при 429 ждёт `ratelimit-reset` (или 60 с) + 2 с, повторяет сетевые сбои и 5xx. Прогон длится минуты.
- 223-ФЗ: время окончания пересчитано из «МСК+N» заказчика; нет пояса — берётся +07 с пометкой.
- Фильтры эвристические (стоп-слова, ОКПД2/КТРУ), не экспертиза ТЗ.
- Вложения/ТЗ с zakupki.gov.ru не скачиваются (сайт с компьютера недоступен). v2test — тестовый контур, состав и свежесть данных могут отличаться от боевого.

## 8. Планировщик
Скрипт запускают рутины Тэндер Мэна (файл 07), cron на компьютере не нужен. Ручной вариант из README: `0 8 * * * cd /workspace/tenders/tender_finder && ./run.sh >> logs/cron.log 2>&1`.

## 9. Если скрипт сломался
- Признаки: `./run.sh` завершается с ошибкой, `--offline-test` не OK, пустые/битые `out/*.csv`, изменился формат ответа GosPlan.
- Главный бот **сам скрипт не переписывает и не правит**, помощники — тоже.
- Тэндер Мэн коротко сообщает Станиславу: текст ошибки, когда началось, что уже проверено (связь, 429, `--offline-test`). Пока скрипт не работает — «Поиск» может временно брать номера вручную через карточки GosPlan в пределах лимита, если Станислав не против.
- **Кто чинит, решает владелец**: например, бот-разработчик или Grok Build CLI с `--reasoning-effort medium` (пример: `grok --cwd /workspace/tenders/tender_finder --reasoning-effort medium -p "<ТЗ на правку>"`; ключи сверить с `grok --help`). Исходное ТЗ скрипта и пример правок — `tender_finder/dev/TASK.md`, `dev/FIX1.md`; спецификация API — `api/fz44.yaml`, `api/fz223.yaml`.
- Требования к любой правке: только стандартная библиотека Python; не гонять живой API при разработке (лимит 10 запросов/мин, работа может быть на паузе) — тестировать на `dev_samples/`; не трогать `seen.json`, `out/`, `cache/`; резервная копия перед правкой; после — `python3 tender_finder.py --offline-test` = OK и обновлённый README.md.
