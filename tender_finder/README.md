# Поиск небольших закупок товаров (44-ФЗ и 223-ФЗ)

Скрипт каждый день собирает закупки Новосибирской области с небольшой НМЦК и оставляет поставку товаров. Услуги, работы, лекарства и медизделия отсекаются; продукты питания и напитки — нет. По умолчанию остаются только запросы котировок (аукционы, конкурсы и запросы предложений убираются).

Источник — REST-зеркало [ГосПлан](https://v2test.gosplan.info) (ЕИС в виде JSON). Сайт zakupki.gov.ru с этой машины недоступен: с нероссийского IP соединение обрывается. Боевой адрес `https://v2.gosplan.info` требует ключ `X-API-Key`. Тестовый `v2test` ключ не просит, но лимит общий и узкий.

Ставить ничего не нужно: Python 3.11+ из стандартной библиотеки (`urllib`, `json`, `csv`, `zoneinfo`).

## Запуск

```sh
./run.sh
# или
python3 tender_finder.py
```

Без аргументов читается `config.json`: регион 54, этап «подача заявок», цена 10–80 тыс. ₽, законы 44 и 223, только запросы котировок, публикация со вчерашних 00:00 (Asia/Krasnoyarsk) до сейчас. Результат:

- `out/ГГГГ-ММ-ДД.csv` — таблица для Excel (UTF-8 с BOM, разделитель `;`);
- `out/ГГГГ-ММ-ДД.md` — короткий отчёт;
- `out/ГГГГ-ММ-ДД.types.json` — сколько извещений каждого типа процедуры попало в список до фильтров.

Повторный запуск в тот же день дописывает в CSV только новые строки (ключ — закон + номер).

Проверка разбора без сети:

```sh
python3 tender_finder.py --offline-test
```

## Параметры командной строки

Они перекрывают `config.json`.

| Параметр | Пример | Смысл |
|---|---|---|
| `--config PATH` | `--config my.json` | другой файл настроек |
| `--laws` | `--laws 44` | `44`, `223` или `44,223` |
| `--region` | `--region 54 --region 22` | код региона, можно несколько раз |
| `--city-only` / `--no-city-only` | `--city-only` | только поставка в г. Новосибирске. У 223-ФЗ, если в адресе лота нет населённого пункта, смотрится почтовый адрес заказчика |
| `--price-min` / `--price-max` | `--price-min 15000 --price-max 60000` | вилка НМЦК, руб. |
| `--stage` | `--stage подача` | `1`/`подача`, `2`/`комиссия`, `3`/`завершена`, `4`/`отменена` |
| `--since` / `--until` | `--since 2026-10-20 --until 2026-10-21` | дата `ГГГГ-ММ-ДД` (00:00 / 23:59:59 Красноярск) или полный ISO |
| `--max-items` | `--max-items 0` | максимум позиций; `0` — не ограничивать |
| `--include` | `--include бумага,салфетк` | оставить, если подстрока есть в предмете или названии позиции |
| `--exclude` | `--exclude канц` | дополнительно выкинуть подстроку |
| `--types` | `--types без-аукционов` | пресет (`quotes`/`котировки` — по умолчанию, `no-auctions`/`без-аукционов`, `all`/`все`, `auctions`/`аукционы`) или белый список кодов. Подробнее — ниже |
| `--count-types` | | только список и распределение типов; карточки и `seen.json` не трогает |
| `--ignore-seen` | | не пропускать уже показанные номера |
| `--no-save-seen` | | не записывать `seen.json` |
| `--max-pages` | `--max-pages 3` | страниц списка по 100 штук |
| `--out-dir` | `--out-dir reports` | каталог отчётов |
| `-v` | | подробный журнал в stderr |

Примеры:

```sh
python3 tender_finder.py --city-only --max-items 1 --laws 44
python3 tender_finder.py --types epNotificationEZK2020,purchaseNoticeZK --since 2026-10-01
python3 tender_finder.py --count-types --stage 1
python3 tender_finder.py --types all --price-max 50000
```

`./run.sh` передаёт все аргументы в `tender_finder.py` как есть (`"$@"`). В `config.json` поле `types` по умолчанию — `quotes` (только запросы котировок). Прежний отбор без аукционов: `./run.sh --types без-аукционов`. Все процедуры, включая аукционы: `./run.sh --types все`.

## Какие процедуры искать

`--types` и поле `types` принимают один и тот же пресет. Регистр не важен, дефис и подчёркивание равнозначны (`без-аукционов` и `без_аукционов`).

| Пресет | Псевдонимы | Что остаётся |
|---|---|---|
| `quotes` | `котировки` | только запросы котировок (значение по умолчанию). Аукционы, конкурсы и запросы предложений отсекаются и по коду извещения, и по способу на карточке |
| `no-auctions` | `без-аукционов`, `без_аукционов`, `no_auctions` | прежнее поведение: без аукционов (котировки, конкурсы и запросы предложений остаются) |
| `all` | `все` | всё, включая аукционы |
| `auctions` | `аукционы` | только аукционы |

Коды котировок 44-ФЗ: `epNotificationEZK2020`, `epNotificationEZK` (и вообще `epNotificationEZK…`). Коды 223-ФЗ: `purchaseNoticeZK`, `purchaseNoticeZKESMBO` (и вообще `purchaseNoticeZK…`). Общий код 223-ФЗ `purchaseNotice` и `purchaseNoticeIS` на списке не выбрасываются: способ читается с карточки. В режиме котировок такая карточка остаётся, только если способ — запрос котировок (или «запрос цен»).

В режиме котировок отсекаются:

- аукционы — коды из `auction_types` и коды с шаблоном EF/EA/AE/OA (`epNotificationEF2020`, `purchaseNoticeAE`, `purchaseNoticeOA` и похожие); в способе — слово «аукцион»;
- конкурсы — `epNotificationEOK…`, `purchaseNoticeOK`, `purchaseNoticeKESMBO` (шаблон OK/KESMBO, но не ЗК МСП `purchaseNoticeZKESMBO`); в способе — слово «конкурс»;
- запросы предложений — `purchaseNoticeZP`, `purchaseNoticeZPESMBO`, `epNotificationEZP…`; в способе — «запрос предложений».

Слово «котировок» в способе само по себе исключение не отменяет: если рядом «аукцион», «конкурс» или «запрос предложений», карточка отбрасывается даже при коде запроса котировок. Код конкурса, аукциона или запроса предложений отбрасывается и на списке, и на карточке. В режиме `no-auctions` аукцион по-прежнему ловится кодом из `auction_types` и словом «аукцион» в способе; конкурсы и запросы предложений остаются. `all` этот фильтр не включает.

Любая другая строка — белый список `purchase_type` через запятую. В JSON по-прежнему можно задать массив кодов.

```sh
./run.sh --types все
./run.sh --types котировки
./run.sh --types аукционы
./run.sh --types без-аукционов
./run.sh --types epNotificationEZK2020,purchaseNoticeZK
```

## config.json

Поля: `laws`, `region`, `city_only`, `city_regex`, `price_min`, `price_max`, `stage`, `since`, `until` (`null` — вчера 00:00 и «сейчас»), `max_items`, `include_keywords`, `exclude_keywords`, `stop_words` (куски регулярных выражений), `exclude_medical_flag`, `okpd2_exclude_prefixes`, `types`, `auction_types`, `base_url`, `min_interval_s` (пауза между запросами, по умолчанию 6.5 с), `max_pages`, `cache_ttl_hours`, `out_dir`, `seen_file`.

`exclude_medical_flag` (по умолчанию `true`): у 44-ФЗ карточка отбрасывается, если у любой позиции внутри `purchaseObjectsInfo` стоит `isMedicalProduct` = `true`. В воронке это отдельная строка «отсеяно: медизделие». При `false` флаг не проверяется.

`okpd2_exclude_prefixes` включает `20.59.52` (диагностические реагенты), `21` (лекарства), `32.50` (медизделия), `26.6`. Префиксы `10` и `11` (продукты питания и напитки) не исключаются.

Адрес API ещё можно задать переменной `GOSPLAN_BASE` (она важнее `base_url`). Ключ боевого контура — `GOSPLAN_KEY` (заголовок `X-API-Key`), в файл его не кладите.

`types`: пресет или список кодов, см. раздел «Какие процедуры искать». По умолчанию в `config.json` стоит `quotes`: только запросы котировок. Аукционы, конкурсы и запросы предложений убираются по коду извещения и по названию способа («аукцион», «конкурс», «запрос предложений»). Слово «котировок» в способе эти слова не перекрывает. `no-auctions` — прежнее поведение: аукционы убираются по коду и по слову «аукцион», конкурсы и запросы предложений остаются. `all` фильтр типов не включает. Строка или JSON-массив кодов оставляют только перечисленные `purchase_type`. Старый отбор: `./run.sh --types без-аукционов`. Все процедуры: `./run.sh --types все`.

Стоп-слова отсекают услуги, работы, лекарства и медизделия. Продукты питания и напитки (в том числе ОКПД2 `10` и `11`) больше не фильтруются. Среди стоп-слов остаются «питательн», «ИВД», «in vitro» и «диагностическ» (питательные среды и диагностика), а также лекарства, медизделия, услуги и работы. Топливо (бензин, дизель) не режется. Слово «медицинск» задевает и «мебель медицинского кабинета» — это ожидаемо. «Рабочие перчатки» не считаются работами.

## Колонки CSV

закон; номер; ссылка; предмет; позиции (`название — количество единица`, через ` | `); кол-во позиций; НМЦК; цена за единицу; заказчик; адрес поставки; окончание подачи; способ; площадка; обеспечение заявки %; обеспечение контракта %; СМП; нацрежим; опубликовано; тип (purchase_type).

Время в отчёте — Asia/Krasnoyarsk, вид `ДД.ММ.ГГГГ ЧЧ:ММ`. У 44-ФЗ доля обеспечения берётся из `part`, иначе считается от суммы и НМЦК: `1% (360 ₽)`. Если поля нет — `нет`. У 223-ФЗ в карточке часто нет суммы обеспечения, тогда `н/д (см. документацию)`. Цена за единицу у 223-ФЗ: из позиции, либо при единственной позиции `≈сумма (НМЦК/кол-во)`. Несколько лотов 223-ФЗ — отдельные строки `НОМЕР лот K`.

В CSV числа с точкой и без пробелов (`65794.00`). В `.md` у каждой закупки есть «цена за ед.»; НМЦК и цена за единицу пишутся с тонким пробелом и запятой: `65 794,00 ₽`.

Позиция 223-ФЗ: если в `lotItem` есть `additionalInfo`, `commodityName` или `name`, в название берётся первое из них. Иначе — имя ОКПД2.

Адрес поставки 223-ФЗ — это `deliveryPlace.address` лота. Если в нём нет населённого пункта (нет «г.», «город», «Новосибирск», «р-н», «обл»), к строке дописывается ` [адрес заказчика: …]` из `customer.mainInfo.postalAddress`. Для `--city-only` берётся адрес лота, если пункт в нём есть, иначе почтовый адрес заказчика.

Ссылка 44-ФЗ — из извещения, иначе типовая карточка ЕИС. Ссылка 223-ФЗ — карточка извещения на zakupki.gov.ru.

## seen.json

Файл `seen.json`: `{"44:НОМЕР": "2026-10-21"}` — день, когда закупка впервые попала в выдачу. На следующем запуске такие номера не показываются снова. Отсеянные фильтром номера в файл не пишутся: если ослабить фильтр, они могут выйти позже. Карточка лежит в `cache/44/` или `cache/223/` и переиспользуется `cache_ttl_hours` часов. `--ignore-seen` отключает пропуск, `--no-save-seen` отключает запись.

## Планировщик

Красноярск/Новосибирск, каждый день в 08:00:

```cron
0 8 * * * cd /путь/к/tender_finder && ./run.sh >> logs/cron.log 2>&1
```

## Ограничения

Лимит ГосПлан — около 10 запросов в минуту. Скрипт держит паузу ≥ 6.5 с, при ответе 429 ждёт `ratelimit-reset` (или 60 с) плюс 2 с и повторяет сбой сети и коды 5xx. На длинном списке прогон занимает минуты: число карточек примерно равно числу кандидатов после дешёвого фильтра.

Часовой пояс 223-ФЗ в карточке задан как «МСК+N» (к UTC прибавляется 3+N). Если пояса нет, берётся +07 и в сроке стоит пометка.
223-ФЗ: время окончания пересчитано из местного времени заказчика (МСК+N из карточки).
Дата публикации 223-ФЗ на списке считается так же, клиентски она не перепроверяется — только серверный `published_after` / `published_before`. У 44-ФЗ дата списка — наивный UTC, она ещё раз сверяется с окном.

Фильтры эвристические: стоп-слова и префиксы ОКПД2/КТРУ, не экспертиза ТЗ. Вложения и техзадание с zakupki.gov.ru отсюда не скачиваются. `v2test.gosplan.info` — тестовый контур, состав и свежесть данных могут отличаться от боя.
